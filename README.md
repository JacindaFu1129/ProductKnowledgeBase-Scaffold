# 业务知识库 · 脚手架

把「用 AI 把设计稿 / 白皮书沉淀成可持续维护的业务知识库」这套方法，做成**任何业务线都能复制即用**的脚手架。

核心思想：**只维护一套"活知识库"（业务认知 + 变更记录），讲解 HTML、说明稿等都是按需生成、用完可丢的快照。**

> 本方法已在两条真实业务线上完整落地验证。

## 这套方法解决什么
一条业务线的知识散在设计稿、白皮书、老同事脑子里。这套方法把它**一次性沉淀成结构化知识库**，之后：
- **新人交接** → 读业务认知建立心智模型；
- **版本设计咨询 / 历史回溯** → 查变更记录溯源；
- **跨业务说明 / 培训** → 从知识库按需生成讲解 HTML 等产出。

## 两种角色
| 角色 | 是谁 | 手上有什么 | 做什么 |
|---|---|---|---|
| **维护者** | 该业务线的设计负责人（每条线 1 人） | 完整工作台（**含 `设计源/` 原始素材**） | 沉淀与更新知识库，推送版本 |
| **使用者** | 新人 / 其他设计师 / 跨组 / 产品研发 | 只需拉取知识库（**轻量文本，不含设计源**） | 读知识、提问、生成自己要的产出 |

> 分界：**只有维护者改 `业务认知/` 和 `变更记录.md`**；使用者只读、只生成产出，发现问题反馈给维护者（或提 MR）。

# A. 维护者的流程

## A0 准备（仅首次）
- **一个 AI 编码工具**：Codex / Claude Code / Qoder 等，能打开本地文件夹和你一起工作。
- **要提炼的物料**，建议命名都带版本，方便溯源：
  - **设计画板**：按版本分文件夹（如 `v3.2/`），画板名带需求号。
  - **环境截图**：文件夹带版本号（如 `v3.1.5环境截图/`）。
  - **技术白皮书**：文件名或内容里注明版本（如 `xx白皮书_v2.4`）。

## A1 首次建库
1. **开工**：用 AI 打开这个脚手架文件夹，说一句——
   > "请根据这个文件夹，跟我一起对 **<产品>** 的 **<业务线>** 做业务知识沉淀。"

   AI 会复制骨架、按业务线命名新目录、并按你说的业务模块把占位符和模块文件建好。
2. **放材料**：把准备好的物料放进新建 KB 的 `设计源/`（只增不改）。
3. **AI 提取**：让 AI "读设计源、按 AGENTS.md 规范提取"。它会切片读图 → 写业务认知 → 记变更 → 更新索引。
4. **你评审**：重点看两点——概念有没有混进版本号 / 交互细节（那些该在变更记录）、有没有理解错。
5. **推送**：确认 `.gitignore` 已就位（设计源/产出/临时件不入库），首次提交推送。

## A2 版本迭代归档（最常态）
每次版本发布后做一次：
1. 把该版本新增/改动的画板、环境截图放进 `设计源/v<新版本>/`。
2. 告诉 AI："提取 v<新版本> 的变更"。它**只读未提取的图**（靠 `索引.md` 判断），然后：
   - **默认**：把"谁在哪个版本因哪个需求改了什么"追加进 `变更记录.md`；
   - **仅当业务概念真的变了**（如新增一类实体、规则本质改变）才动 `业务认知/`；
   - 更新 `索引.md` 状态。
3. 你评审 → commit & push。

> 关键判断：**大多数版本迭代只该动变更记录，不动业务认知。** 若 AI 往业务认知里塞了版本号或弹窗细节，打回。

## A3 澄清存疑 / 纠错
- 发现知识与最新产品不符：直接让 AI 改 `业务认知/`，并在 `变更记录.md` 说明。
- 拿不准、或与旧基线冲突：**不改**，在 `00_总览.md` 的"存疑"区登记，之后澄清。

## A4 补认知基础（白皮书等）
拿到白皮书 / 基线文档时：放进 `设计源/` → 让 AI **只用它填补空白**（当前无冲突陈述的部分）；与现状明确不一致的，登记存疑，**不覆盖现有知识**。

# B. 使用者的流程

## B0 拉取
`git clone` 该业务线的知识库。拿到的是**纯文本知识**（几百 KB，秒拉）——不含设计源、不含生成过的产出。
要看原始画板时，找维护者或去共享盘（见该库 `变更记录.md` 里的需求号与设计源文件名）。

## B1 新人上手 / 交接
1. 先读 `业务认知/00_总览.md`——菜单地图 + 主流程 + 心智模型。
2. 再按需读 `业务认知/<模块>.md`。
3. 有疑问直接问 AI（在该目录里）："<某概念>是什么/为什么这么设计"——它基于知识库回答。

## B2 做版本设计前的咨询
查 `变更记录.md`：这个模块历史上改过什么、为什么改、哪个需求号，避免重复踩坑或推翻已有结论。

## B3 历史问题回溯
在 `变更记录.md` 按模块/需求号定位条目 → 拿到版本、原因、设计源文件名 → 需要看原图再去找素材。

## B4 跨业务说明 / 培训材料
让 AI "从知识库生成一份 XX（讲解 HTML / 说明稿 / 交接清单）" → 落到你本地 `产出/`。
**产出是快照**：不提交、不长期维护，知识库更新后随时重生。

## B5 日常答疑
直接问 AI 具体业务问题（如"一辆车既是名单车又买了包期，怎么计费"）。它只读 `业务认知/` + `变更记录.md` 作答，不重扫图片。
若发现答案与实际不符 → 反馈给维护者（走 A3）。
