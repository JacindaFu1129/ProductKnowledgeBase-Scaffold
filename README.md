# 业务知识库 · 脚手架

把「用 AI 把设计稿 / 白皮书沉淀成可持续维护的业务知识库」这套方法，做成**任何业务线都能复制即用**的脚手架。

核心思想：**只维护一套"活知识库"（业务认知 + 变更记录），讲解 HTML、说明稿等都是按需生成、用完可丢的快照。**

> 两个已建成的实例可参考：`../hcp-3rdpartyintegration-kb-main`（三方集成）、`../hcp-parking-kb`（停车场）。

## 这套方法解决什么
一条业务线的知识散在设计稿、白皮书、老同事脑子里。这套方法把它**一次性沉淀成结构化知识库**，之后：
- **新人交接** → 读业务认知建立心智模型；
- **版本设计咨询 / 历史回溯** → 查变更记录溯源；
- **跨业务说明 / 培训** → 从知识库按需生成讲解 HTML 等产出。

---

## 第 0 步：准备

- **一个 AI 编码工具**：Codex / Claude Code / Qoder 等，能打开本地文件夹和你一起工作。
- **要提炼的物料**，建议命名都带上版本，方便后续溯源：
  - **设计画板**：按版本分文件夹（如 `v3.2/`），画板名带需求号。
  - **环境截图**：文件夹带版本号（如 `v3.1.5环境截图/`）。
  - **技术白皮书**：文件名或内容里注明更新版本（如 `xx白皮书_v2.4`）。

## 怎么用

1. **开工**：用 AI 打开这个脚手架文件夹，说一句——
   > "请根据这个文件夹，跟我一起对 **<产品>** 的 **<业务线>** 做业务知识沉淀。"

   AI 会复制骨架、按业务线命名新目录、并按你说的业务模块把占位符和模块文件建好。
2. **放材料**：把准备好的物料放进新建 KB 的 `设计源/`（只增不改）。
3. **AI 提取**：让 AI "读设计源、按 CLAUDE.md 规范提取"。它会切片读图 → 写业务认知 → 记变更 → 更新索引。
4. **你评审**：重点看两点——概念有没有混进版本号 / 交互细节（那些该在变更记录）、有没有理解错（不一致就让它改，或打存疑标签）。
5. **按需出产出**：要培训 HTML / 说明稿 / 交接清单时，让 AI 从知识库生成到 `产出/`；产出不长期维护，随时可重生。

分工：**人策展物料 + 评审产出，AI 提取与整理。**
